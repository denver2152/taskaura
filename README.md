# TASKAURA

**Plan with purpose. Execute with clarity.**

Taskaura is a full stack task and project management workspace built with React, Express, and MongoDB. It gives individuals and small teams a calm place to plan work, track progress, and understand what is next.

## Features

- Registration and login with bcrypt password hashing and signed JWT sessions.
- New account sign-up and password recovery use Brevo email codes; codes expire after 10 minutes and allow five verification attempts.
- Password change and reset revoke all older sessions; account deletion requires password confirmation and safely transfers workspace ownership when needed.
- Workspace isolated task and project CRUD with server side validation and role checks.
- Kanban and list task views, priorities, start and due dates, tags, subtasks, comments, task duplication, archiving, restoration, and recorded focus sessions.
- Projects support editable status, dates, milestones, colors, and progress calculated from active task records.
- Month calendar based on task deadlines; Pomodoro focus rounds (25/5/15) persist across navigation and save session history to MongoDB.
- Calendar month, week, day, and agenda views with project filtering and due-date rescheduling.
- Global debounced workspace search across tasks, projects, members, and task comments; results are limited to the active workspace.
- Rule-based Taskaura Insights for weekly activity, overdue and near-deadline tasks, workload checks, and a transparent lightest-deadline-day suggestion.
- Workspace invitations by email, role management and member removal for administrators, and multi-workspace switching.
- Dashboard and reporting data calculated from MongoDB records.
- CSV report export, responsive layouts, and light/dark themes.
- Deadline reminders generated by an authenticated daily Vercel Cron endpoint, with per-user duplicate protection.
- Vercel compatible Express handler with cached MongoDB connections.

Brevo is required for new sign-ups, password recovery, and workspace invitations. Permanent task attachments and external file storage are not implemented yet.

## Technology

React 18, Vite, Tailwind CSS, React Router, Zustand, React Hook Form, Zod, Axios, Lucide, Recharts, dnd-kit, Sonner, date-fns, Node.js, Express, MongoDB, Mongoose, JWT, bcrypt, Helmet, CORS, and express-rate-limit.

## Local development

Requirements: Node.js 20 or newer and a local MongoDB instance or MongoDB Atlas database.

1. Install dependencies from the repository root: `npm install`, `npm install --prefix server`, `npm install --prefix client`.
2. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI` and a random `JWT_SECRET` of at least 32 characters. Set `CLIENT_URL=http://localhost:5173`.
3. Copy `client/.env.example` to `client/.env` if the API will not run at `http://localhost:5000/api`.
4. Start both services with `npm run dev`.
5. Open `http://localhost:5173`, create an account, and add tasks/projects.

### Configure Brevo email verification

In Brevo, create an API key with Transactional email permission and verify the sender address or sending domain. Add `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, and optionally `BREVO_SENDER_NAME=TASKAURA` to `server/.env` (never `client/.env`). Restart the API. Sign-up and password recovery use six-digit codes that expire after 10 minutes, allow five attempts, and can be resent after 60 seconds. Workspace invitations are sent to the invited email and expire after seven days. See [Brevo's transactional email guide](https://developers.brevo.com/docs/send-a-transactional-email) and [sender setup guide](https://developers.brevo.com/docs/getting-started-with-senders-and-domains).

`npm run dev:server` and `npm run dev:client` start services individually. The API health endpoint is `/api/health`.

To create optional development sample data, set `SEED_PASSWORD` to a private value of at least 12 characters in your current shell and run `npm run seed`. The seed command creates `demo@taskaura.local` with one sample project and tasks, and leaves an existing demo account unchanged.

## MongoDB

For local development, start MongoDB and use `mongodb://127.0.0.1:27017/taskaura`. For Atlas, create a database user with a strong password, add the deployment's outbound IP range (or the network range your provider requires) in Atlas Network Access, and set the Atlas connection string as `MONGODB_URI` on the backend. Never place the URI in a `VITE_` variable. The application creates collections on first use; there is no production seed data.

## Deploy to Vercel

1. Push this repository to GitHub and import it into Vercel.
2. Use the repository root as the project root. Vercel builds the frontend from `client` and exposes `api/index.js` as the serverless Express handler.
3. Add `MONGODB_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `CLIENT_URL`, `NODE_ENV=production`, `BREVO_API_KEY`, and `BREVO_SENDER_EMAIL` to the Vercel project environment. Use your deployed site URL for `CLIENT_URL`.
4. Configure Atlas network access and verify `/api/health`, registration, login, and one task create/read/update flow against the deployed URL.
5. Redeploy after changing environment variables.

The frontend uses same-origin `/api` requests by default in production. The local dev API default is `http://localhost:5000/api`.

## GitHub

Create a repository, then run `git init`, `git add .`, `git commit -m "Build Taskaura project management app"`, `git branch -M main`, and `git push -u origin main` after adding your GitHub remote. Do not commit `.env` files; they are ignored.

## Environment variables

See `server/.env.example` and `client/.env.example`. Brevo credentials are required for sign-up verification, password recovery, and team invitations. Set `CRON_SECRET` in Vercel to protect the scheduled `/api/cron/reminders` endpoint. The endpoint creates reminders for assigned tasks due within 24 hours or overdue. Attachments and external file storage are not implemented, so the core application does not accept permanent file uploads.

## Quality checks

Run `npm run build` for the production frontend build. API integration depends on a reachable MongoDB instance. Run `npm --prefix server test` for backend unit tests covering OTP hashing and session-version revocation. The frontend production build is checked with `npm run build`. API integration tests against MongoDB remain to be added.
